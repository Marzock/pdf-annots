# pdf_annotations.py

Reads annotations out of PDF files - highlights, underlines, notes, boxes,
freehand drawings - and writes them out as a Markdown table: one
`annotations.md` per directory next to the PDFs, or everything collected into a
single file.

Meant as a bridge between reading and writing: you highlight in your PDF
reader, and the quotes end up as searchable text right beside the papers.

## Requirements

- Python 3.9 or newer
- [PyMuPDF](https://pymupdf.readthedocs.io/) - installed automatically on the
  first run (see [Environment](#environment))
- Internet access once, for that first run; never again afterwards

## Installation

The script is a single file with nothing else attached. Drop it somewhere, make
it executable, done:

```sh
chmod +x pdf_annotations.py
./pdf_annotations.py --version
```

To call it from anywhere, put it on your `PATH`:

```sh
install -m 755 pdf_annotations.py ~/.local/bin/pdf-annots
```

## Usage

```sh
./pdf_annotations.py                            # PDFs in the current directory
./pdf_annotations.py ~/literature               # PDFs below any path
./pdf_annotations.py literature papers/x.pdf    # several paths, single files too
./pdf_annotations.py ~/literature -o all.md     # one collected file instead of per directory
./pdf_annotations.py paper.pdf -o -             # table to stdout
./pdf_annotations.py ~/literature --watch       # keep watching
./pdf_annotations.py ~/literature --watch &     # in the background
```

With no path given, the current directory is searched, subdirectories included
by default. Hidden files and directories (those starting with `.`) are skipped.

## Output

Each directory gets a file like this one:

```markdown
# Annotations - literature

<!-- generated by pdf_annotations.py - do not edit by hand -->

2 annotations from 1 PDF file.

| Source     | Page | Section       | Type      | Color  | Result                                     |
| ---------- | ---- | ------------- | --------- | ------ | ------------------------------------------ |
| smith-2024 | 4    | 2 Methodology | highlight | yellow | we sampled 40 subjects — *sample is small* |
| smith-2024 | 9    | 5 Discussion  | note      | blue   | *cf. Meyer 2019*                           |
```

### Columns

`Source` (the PDF name, with a relative path in the collected file) · `Page` ·
`Section` · `Type` · `Color` · `Result`. `--with-author-date` adds `Author` and
`Date`. Empty fields show up as `-`.

`Result` holds the highlighted original text and your own comment in one cell:
the comment is set in *italics* and, where there is both, follows the quoted
text after an em dash. `--max-cell` applies to each of the two parts.

`Section` comes from the PDF's table of contents: the last outline entry above
the annotation. Without a table of contents it stays `-`.

Rows are sorted by file name, page, and position on the page.

## Options

| Option | Meaning |
|---|---|
| `PATH ...` | directories and/or PDF files (default: current directory) |
| `-o, --output FILE` | write everything into **one** file, `-` = stdout |
| `--output-name NAME` | file name per directory (default: `annotations.md`) |
| `--title TEXT` | heading of the collected file (default: name of the first path) |
| `--no-recursive` | do not search subdirectories |
| `--watch` | keep watching instead of running once |
| `--interval N` | poll interval in seconds for `--watch` (default: `2`) |
| `--with-author-date` | additional columns `Author` and `Date` |
| `--max-cell N` | truncate quote/note after N characters, `0` = unlimited (default: `300`) |
| `--exclude PATTERN` | skip a glob pattern (can be given more than once) |
| `--no-default-excludes` | turn off the default excludes (`*/build/*`, `*/out/*`) |
| `--dry-run` | only report, write nothing |
| `--venv PATH` | environment for PyMuPDF elsewhere (also via `PDF_ANNOTS_VENV`) |
| `--no-bootstrap` | do not install PyMuPDF automatically, bail out instead |
| `--root DIR` | legacy spelling for a positional argument (still supported) |
| `--version` | print the version |

Exit status `0` on success, `2` on bad arguments (a path that does not exist,
`--watch` together with `-o -`).

## Recognized annotations

| In the PDF | In the table |
|---|---|
| Highlight, Underline, StrikeOut, Squiggly | highlight, underline, strikeout, squiggly |
| Square, Circle, Ink, Polygon, PolyLine, Caret | box, ellipse, freehand, polygon, polyline, caret |
| Text, FreeText, Stamp, FileAttachment | note, text box, stamp, attachment |

Internal link annotations (hundreds of them in some PDFs), popups and form
fields are ignored - they are not reading notes. Annotations with neither
highlighted text **nor** a comment are dropped as well.

The annotation color is rounded to the nearest name: `yellow`, `orange`, `red`,
`pink`, `purple`, `blue`, `cyan`, `green`, `gray`, `black`, `white`.

## Watch mode

`--watch` checks modification time and size of every PDF at the chosen
interval. When something changes, the script waits until the file has settled -
Preview and Skim write in several steps - and then re-extracts. Stop it with
`Ctrl-C`. `--watch` and `-o -` are mutually exclusive.

## Environment

If PyMuPDF cannot be imported, the script sets up a virtual environment of its
own, installs `pymupdf>=1.24` and restarts inside it. It looks in this order:

1. `--venv PATH` resp. `PDF_ANNOTS_VENV`
2. `.venv` next to the script
3. `$XDG_CACHE_HOME/pdf-annots/venv`, otherwise `~/.cache/pdf-annots/venv`

What gets *created* is always the last of these, the cache path, unless
`--venv` or `PDF_ANNOTS_VENV` points somewhere else. To manage PyMuPDF
yourself, use `--no-bootstrap`; the script then bails out with an installation
hint.

## Writing files

- The output file is only rewritten when its content has actually changed.
- A file **without** the auto marker in its head is never overwritten - your
  own notes are safe, though they are better off in a separate file.
- When all annotations in a directory are gone, the auto-generated
  `annotations.md` there is removed too (per-directory mode only).
- `--dry-run` shows what would happen and writes nothing.

## Getting annotations into the PDF

The script only reads what is really stored in the PDF file:

- **Preview** and **Adobe Acrobat** save annotations into the PDF when you
  save.
- **Skim** keeps notes separately by default. There, use
  "File → Export/Embed Notes" or save as PDF.
- **Zotero**, **Mendeley** and similar managers partly hold annotations in
  their own database - export them into the PDF first.
